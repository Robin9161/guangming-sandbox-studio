# 沙盘深圳 · 美术风格与设计规范

> **给接手的人和 AI**：动任何画面相关的代码之前，先读完这份文档。
> 这里记录的是已经和项目负责人反复调过、确认过的风格。新做的东西要沿用它；想改其中的规则，先和负责人确认，再同步改这份文档（文末有变更记录）。
> 文档里的数字都对应代码里的实际取值，标了出处（路径相对 `app/sandbox/`）。**代码和文档对不上时，以代码为准，并把文档改正。**
> 本文从「光明沙盘 Studio」的规范移植而来（2026-10-21），已按本工程的实际代码和规则改过（例如本工程"雾平时不出现"、正午用马卡龙配色）。

## 1. 风格定位

**一句话：浅色微缩沙盘，让天光来上色。**

- **三种画面模式**（右侧面板）：☀ 白天（经典马卡龙配色）、☾ 夜晚、✦ 光影（连续的一天 + 日出日落氛围 + 天气）。光影模式的正午 = 白天的马卡龙配色。
- **白天**：奶油白的建筑体块、浅土色地面、马卡龙绿的山和树、灰蓝的路网，像一个精致的实体沙盘模型。物体本身颜色很浅、很素，画面的情绪全靠一天中变化的光色。
- **黄昏和清晨**：天空和远处的雾可以很浓烈（粉、橙、紫），地面和建筑只带一点同色调的倾向。
- **夜晚**：城市是深蓝的渐变剪影，只有少数高楼成排亮起暖黄的窗，主干道有冷白的 LED 路灯，远处是暖色的灯光点；少数真实的地标有一种颜色的夜光（如虹桥的红）。
- **整体**：有微缩模型摄影的质感（接缝处的柔和暗部、画面上下轻微虚化、暗角），远景层层溶进地平线色的空气里。
- **镜头**：一律北在上，不大角度旋转。

风格来源：

1. 《无尽动画》项目（借鉴 ALTO 系列游戏的配色方法）：一天的配色由少数关键色派生，雾色 = 地平线色，关键帧之间在 OKLCH 色彩空间插值。
2. 水粉画的城市夜景：楼体是从下往上变暗的剪影，远处的灯是暖色的，与冷色的楼体形成反差。
3. 微缩模型摄影：移轴虚化、柔和的环境光遮蔽。

用途：讲解剧本（网页里自动讲解光明），以及**做视频里的三维动画镜头**（4K60 成片，航拍、全景为主，偶尔推近）。做视频时所有风格决定都优先考虑"作为视频画面好不好看"。

## 2. 核心原则

每条原则都写了原因。新做的效果先对照这几条。

### P1 整帧颜色只由少数关键色派生

一帧画面里的所有颜色只来自这几个随时间变化的关键色：

| 关键色 | 用在哪里 |
|---|---|
| 天顶 `top`、天中 `mid`、地平线 `horizon` | 天空穹顶三段渐变 |
| 雾色 `fog`（默认 = 地平线色） | 距离雾、体积雾、远山 |
| 阳光 `sun` + 强度 `sunI` | 太阳（夜里是月光） |
| 天光 `sky`、地光 `ground` + 强度 `hemiI` | 半球光 |
| 暗部色 `shadow`、亮部色 `high` + 强度 `grade`、饱和度 `sat` | 全局调色 |
| 空气感 `haze`、夜间系数 `night` | 雾的远近；夜景、星星、泛光 |

**原因**：颜色从同一组关键色派生，任何时刻画面都是协调的；改一处，整帧一起变。
**规则**：新做的东西不要自己写死一个"好看的颜色"，要从这些关键色取（`scene/atmosphere.ts` 里的 `look.colors`，或 `nightUniform` 这类全局 uniform）。
出处：`scene/artPalette.ts`、`scene/atmosphere.ts`

### P2 雾色 = 地平线色，远处的东西没有自己的颜色

远景按距离溶进地平线色（空气透视）。远处的山、楼、水面不需要也不应该有独立配色。

**原因**：这是 ALTO 风格的空间感来源，层次靠"多远就多像天边"来表现。
出处：`scene/atmosphere.ts` 的 `fogBase`（距离雾）。

### P3 克制：浓烈的颜色只给天空和远处的雾

照到地面和建筑上的光，只带一点天空颜色的倾向。

```
RESTRAINT = { lightChroma: 0.55, moodOnLight: 0.25, grade: 0.55 }
```

- `lightChroma`：阳光、天光、地光、调色色只保留 55% 的彩度
- `moodOnLight`：日出日落的"氛围"作用到光照上只有 25%（天空是全量）
- `grade`：全局调色强度再乘 0.55

**原因**：负责人的原话是"核心是地面还有建筑颜色太过浓烈，天空还好"。玫瑰、紫暮这类氛围之前把整个城市染成粉紫色，很难看。
**规则**：不要为了"更有氛围"而调高这三个数。想要更浓烈的感觉，改天空关键色。
出处：`scene/artPalette.ts`

### P4 颜色插值在 OKLCH 里做，冷暖之间绕品红走

关键帧之间在 OKLCH 里插值；从冷色到暖色时，色相绕品红一侧走（青 → 蓝紫 → 粉 → 橙）。

**原因**：直接按 RGB 插值，日落时会经过一段发灰发脏的颜色。绕品红走，过渡是干净的粉紫。
**规则**：新增随时间变化的颜色，用 `artPalette.ts` 里的插值函数，不要自己线性混合 RGB。

### P5 物体本色浅、低饱和，让光来上色

| 物体 | 颜色 | 出处（`scene/palette.ts`） |
|---|---|---|
| 建筑 | `#f8f6f1` `#f3f1ec` `#f6f5f2` 等奶油白；屋顶略亮 | buildingColors |
| 城区地面 | `#efe5cf` | ground.urban |
| 山体绿（按海拔 55 / 100 / 160 / 230 m 分阶） | `#a9cf86` `#93c274` `#7fb365` `#6c9f58` | ground.hills |
| 区界外 | 逐渐褪到底板色 `#ebe6da`（最多 80%） | context |
| 树冠 | `#7fbf5f` `#94cc6a` `#6aad55` `#a6d477` | trees.crowns |
| 道路（按等级由深到浅） | `#6f7787` … `#a9afb9` | roadStyle |
| 大道中央绿带 | `#8fc46f` | avenueMedian |
| 水 | 基础色 `#7fd3e0`，实际颜色随天光变化（见第 7 节） | water |
| 精细地标 | 银 `#dde2e8`、石 `#ede4d3`、白 `#fbfbf9` 等，放大约 1.3 倍 | landmarkStyle |
| 地铁 / 高铁 | 官方线路色（6 号线 `#3ABCA8`、13 号线 `#DE7C00`、6 号线支线 `#037776`） | sandbox.json meta.lineColors |

**原因**：物体颜色越浅越素，天光的颜色越能体现出来；饱和的物体色会和天光打架。
**规则**：新增物体（地标、交通、人流等）也用浅色、低饱和；需要强调的东西靠光（夜光、轮廓光、聚光灯）而不是靠高饱和的固有色。

### P6 夜景：渐变剪影 + 少量暖窗 + 冷暖反差

- 楼体在夜里是**竖向渐变的剪影**：楼脚偏亮的蓝（`0.02, 0.035, 0.12`）→ 楼顶近黑的藏青（`0.004, 0.006, 0.022`）。不同朝向的墙深浅略有不同，体块不会糊成一片。
- 楼体换成剪影要比天色变暗得**更快**（夜间系数 0.1 → 0.55 之间完成），蓝调时刻就已经是剪影。否则残留的白天浅色会让墙发灰，"像蒙了一层雾"。
- **只有高楼亮灯**：楼高 32 m 以下基本不亮，70 m 以上亮得最多；同一层的窗大多一起亮（"成排亮"）。商业区的高楼亮得多，工业区基本黑着（片区活跃度）。
- 窗灯是单一的柔和暖黄白（`1.0, 0.8, 0.48`）。远处窗格小于一个像素时，只留很淡的平均光，避免整面墙均匀发光像灯箱。
- 推近时，没亮的窗是很暗的蓝玻璃，立面有质感，不是一块死黑。
- 路灯是冷白 LED（`#cfe0ff`）：只照亮主干道和次干道的路面、路边的地面、树和楼脚，支路不亮。远处是暖色的灯光点（楼顶和主干道），近处主干道两侧有暖色小光点。
- 亮灯比例随时间变化：18:18 开始亮，20:00 到最多；22:00 以后逐渐熄掉一部分；凌晨 4:30–6:00 全部熄灭。（经典「夜晚」模式固定 0.24。）
- 夜里移轴减弱（`tilt = 1 − 0.85·night`）、AO 关掉，不让小光点被糊掉；泛光增强。

**原因**：负责人反馈过"晚上的建筑发光很难看""亮成了一片"。参考了水粉画后确认，城市夜景的美感来自冷色剪影和少量暖光的反差，而不是灯多。
**规则**：不要给所有楼都加灯，不要提高亮灯比例让城市"更热闹"，不要用白色或多种颜色的窗光。
出处：`scene/buildings.ts`、`scene/nightLight.ts`、`scene/cityDots.ts`、`studio/streetLights.ts`、`scene/atmosphere.ts`（`windowLitUniform`）

### P7 彩色光：少、真实、单色

- 只给**少数**有现实依据的地标加彩色夜光，每个地标**只用一种颜色**。
- 现有：**虹桥**（虹桥公园的红色步道桥，现实中夜里是红光）：栏杆 `#ff3a2c` × 2.4（勾出整条红飘带），桥面 `#ff4a3a` × 0.4、桥墩 `#d0362a` × 0.22；随 `smoothstep(night, 0.15, 0.6)` 亮起。
- 新增彩色光之前，先查证这个地标现实中夜里是什么颜色的灯；查不到就不加。

**原因**：彩色光是点缀，多了就俗，而且会破坏 P6 的冷暖反差。
出处：`scene/createSandbox.ts`（`landmarkGlows`）

### P8 天气是叠加到当天配色上的，而且慢起慢落

- 天气不自带一套配色，而是把当前时刻的配色往"同亮度的灰蓝"上拉：多云轻，雨重，雷暴最暗。雪变亮变冷，雾变灰、阳光很弱。
- 强度 0–1 慢慢起、慢慢收（约 30 秒）；手动切换时快速收掉旧的（约 1.5 秒）再起新的。
- 地面湿度和积雪比天气本身更慢：下雨约 8 秒变湿，停雨约 60 秒变干；下雪约 45 秒积满，停雪约 2 分钟化完。
- 天气只在「光影」模式下生效。

**原因**：天气是"同一天的不同情绪"，画面始终和时刻协调；突变不像真实天气，也不适合做视频镜头。
出处：`scene/weather.ts`（`applyWeatherToLook`、状态机）

### P9 雨要克制，闪电只在夜里

- 雨丝细、淡、稀：7000 根，宽 0.0005、长 0.03（相对于雨区大小），不透明度 0.42；雨的出现比例是强度 × 0.55（雷暴 × 0.7）。
- 闪电只在**夜里**（夜间系数 > 0.5）的雷暴中出现，随机间隔 3–11 秒，每次闪两下。
- 雪花 9000 片，慢慢飘落、左右摆动。
- 雨雪的颜色跟随天光：白天浅、夜里暗。

**原因**：负责人反馈"雨太大了，少了美感，闪电可以在晚上"。
**规则**：不要加大雨丝的数量、粗细和不透明度来"增强效果"。想表现大雨，用水面涟漪、地面变湿反光、天色变暗来表现。
出处：`scene/weather.ts`

### P10 雾平时不出现；出现时是亮的、通透的

- **雾平时不出现（画面会脏）**：只在讲解「2-3 风从口子进来」那一拍（风吹雾）和手动选「雾」天气时出现。晨雾、晨昏薄霭、雨雪起雾都已去掉，自动天气里也没有雾。
- 体积雾跟着山水走：水边、山谷、林地多，城区少；贴着本地地面衰减，山头从雾里露出来。
- 雾色取雾色和地平线色的中间再提亮 1.1 倍：**雾是亮的、通透的，不是土黄的沙尘**。被逆光照透的雾最好看（太阳照雾在清晨、黄昏最强）。
- 近处的城市保持清楚：距离雾的起点跟着镜头距离走，夜里再往后推。

**原因**：负责人反馈过"建筑有很重的雾感"，并定下"雾平时不出现"。
出处：`scene/atmosphere.ts`（`uGFAmount`）、`scene/volumeFog.ts`

### P11 水：同一色相，用明度、清澈度、倒影区分深浅

详见第 7 节。核心规则：

- 塘、湖、水库是**同一个色相**（原来的马卡龙水色），区别在于明度（深浅）、浑浊度和倒影强度。
- 河道保留原来鲜亮的马卡龙青色（微缩视角下河是一条清楚的线）。
- 岸边有一圈浅色带，离岸越远越深。

**原因**：负责人反馈过"水坑、湖、水库颜色都一样，没有深浅变化"。

### P12 微缩质感

- 环境光遮蔽（GTAO）给出楼与楼、楼与地面接缝处的柔和暗部，微缩模型的质感主要靠它。白天强度 0.85，夜里关闭；远处（18–32 km）不做 AO，避免闪烁。
- 移轴：画面上下边缘轻微虚化（边缘约 3 像素）。
- 暗角：白天 0.9，夜里加到 1.25（VignetteShader 的算法）。
- 高程夸张：低处城区约 1.6 倍，60 m 以上逐渐加到约 2.4 倍（3.2 倍时山体过陡）。**建筑不夸张。**
- 道路按等级加宽（真实宽度的约 1.3–1.5 倍），远看时路网骨架才清楚。

## 3. 一天的配色（关键帧，光影模式）

一天由 10 个关键帧组成，关键帧之间按 smoothstep 缓动、在 OKLCH 里插值。完整数值见 `scene/artPalette.ts` 的 `KEYS`。

| 19:24 | 蓝调 | 深蓝紫，地平线一抹粉；雾色单独设为 `#3c4aa0` | `#1e2c80` `#5a4aa0` `#e07aa8` | 0.62 | — | 0.78 |

- 日出、黄金时刻、日落的阳光加强、天光减弱，明暗对比更足（2026-10-11 调）。

- 夜里月光从西南高处来，方向固定；日出日落前后在两者之间平滑转过去，阴影不跳。

面板上的快捷时刻（`page.tsx`）：日出 6.4、上午 9、正午 12.5、黄金时刻 17.4、日落 18.15、蓝调 19.3、深夜 23。**其中日出、正午、黄金时刻、蓝调、深夜五个是验收画面的标准时刻**（第 10 节）。

### 日出日落的"氛围"

日出日落前后，在天空上叠一层随机的氛围色（天空全量，光照只有 25%）：

| 氛围 | 性格 |
|---|---|
| 素 | 不叠加 |
| 玫瑰 | 粉紫、柔 |
| 余烬 | 深红橙、浓 |
| 紫暮 | 蓝紫 + 珊瑚粉 |
| 金 | 金黄、明亮 |

默认"每天随机"：每到正午和午夜换一种（不会随机到"素"）。

## 4. 天气

| 天气 | 目标强度 | 配色变化 | 其他表现 |
|---|---|---|---|
| 晴 | 0 | 无 | — |
| 多云 | 0.8 | 往灰蓝轻拉（×0.55），阳光弱 55% | 云量增加 |
| 雨 | 0.8 | 往灰蓝拉（×0.85），变暗到 72%，阳光弱 85% | 雨丝、水面涟漪、地面变湿反光、云变灰 |
| 雷暴 | 0.97 | 最暗（55%），阳光弱 92% | 同雨，雨更密（×0.7）、水面波动更大；**夜里**有闪电 |
| 雾 | 0.85 | 变灰（×0.75），阳光弱 65%，饱和度降 | 体积雾（浓度 = 强度），雾层加厚 |
| 雪 | 0.85 | 变亮变冷（×0.7，亮度 108%），阳光弱 55% | 雪花、朝上的面慢慢积雪（路面积雪少一半），云量一半 |

- 自动模式：每隔一两分钟随机换一种天气，中间穿插晴天。出现权重：多云 0.35、雨 0.25、雷暴 0.12、雪 0.12（**没有雾**，见 P10）。
- 手动切换后 4 分钟内不会自动换。
- 天气越重，日出日落的光晕和太阳光晕越弱（天被云遮住）。
- 闪电瞬间把天空和天光照成冷白紫色（`#dcd8ff`），泛光同时增强；同时在镜头焦点附近劈下一道带两根分叉的冷白光（`(4, 3.8, 5)`，靠泛光出光晕）。

新增一种天气要改的地方：`scene/weather.ts`（类型、名称、目标强度、权重、`applyWeatherToLook`）→ `scene/atmosphere.ts`（雾、云的反应）→ `scene/waterGpu.ts`（水面）→ 本节表格。面板按钮由 `WEATHER_ORDER` 自动生成。

## 5. 雾与大气

| 项目 | 规则 | 出处 |
|---|---|---|
| 距离雾（光影模式） | 颜色 = 雾色；起点 ≈ 镜头距离 ×(1 + 0.8·night) / haze，夜里再加 1500 m；终点 ≈ 镜头距离 × 4.2 ×(1 + 0.8·night) / haze + 8000 m；正午马卡龙时退到 70–160 km | atmosphere.ts `fogBase` |
| 距离雾（白天 / 夜晚） | 70–160 km（几乎无雾） | atmosphere.ts |
| 体积雾 | 平时 0；「雾」天气时浓度 = 天气强度；讲风那一拍强制 6 并灌满盆地，再起西南风把雾吹开 | atmosphere.ts、volumeFog.ts |
| 雾的形态 | 两层三维噪声（1400 m 和 520 m 尺度），随风缓慢飘动；按离本地地面的高度指数衰减；雾源图（水边、谷底多，城区少）；雾体边缘 500 m 内渐隐 | volumeFog.ts |
| 太阳照雾 | 0.8 + 1.0 × 光晕 + 0.6 × 清晨；夜里没有 | volumeFog.ts |
| 星星 | 只在夜里、只在地平线以上 | atmosphere.ts |
| 云 | 低多边形的云团，慢慢飘，投下移动的云影；颜色往地平线色靠 35%（正午马卡龙时不靠），夜里变成暗蓝灰；阴雨天变灰、逐朵长出更多的云 | decor.ts、atmosphere.ts |

## 7. 水面

| 等级 | 判定 | 深度上限 | 倒影强度 | 岸边浅色带 | 性格 |
|---|---|---|---|---|---|
| 塘 pond | 数据标为 pond，或面积 < 1 万 m² | 0.3 | 0.35 | 1.0 | 最浅、倒影弱 |
| 湖 lake | 其余 | 0.7 | 0.75 | 0.6 | 标准水色 |
| 水库 reservoir | 数据标为 reservoir，或面积 > 20 万 m² | 1.0 | 1.0 | 0.35 | 最深，倒影像镜面 |
| 河道面 river | 数据标为 river 的水面 | 0.5 | 0.4 | 0.5 | 流动的水 |
| 河道线 | 线状的河、溪、渠 | — | — | — | 保留原来鲜亮的马卡龙青色，不换新水面 |

- 深度 = 近岸浅色带（约 16 m 范围，占三成）+ 离岸越远越深（约 125 m 范围，占七成）× 这一级的深度上限。
- 颜色：以原来的马卡龙水色为主（跟着白天 / 夜晚 / 光影配色变），浅处就是原水色 × 1.04，深处只略往深青 `#2a7f96` 靠（不往泥土色混，否则发灰），夜里收拢到深色；岸边浅色带往 `#f4f1e6` 靠。
- 倒影强度整体打六折：日出日落、蓝调时天空很浓，满倒影会让水面发紫。
- 菲涅尔：从上往下看能看到水的颜色，越斜看越以倒影为主。
- 微波：两层缓慢流动的噪声让倒影轻轻晃动；多云、雨、雷暴时波动依次加大。
- 雨点涟漪：按 8 m 的格子随机冒出扩散的波纹，雨越大越多。雨天深浅差变小、水面变粗糙。

出处：`scene/waterGpu.ts`

## 8. 后期

顺序固定：**场景 → GTAO → 体积雾合成 →（景深）→ 移轴 → 泛光 → 暗角 → 全局调色 → 色调映射 → 3D LUT → 地名标签**（`scene/createSandbox.ts` 的后处理部分）。

| 环节 | 取值 |
|---|---|
| AO | GTAO，全分辨率，半径 60、12 次采样；强度 0.85 × (1 − night)；18–32 km 外不做 |
| 体积雾 | 两层（雾体、太阳照雾），0.35 倍分辨率计算再模糊；遮挡上限 0.95 |
| 景深 | 默认关（「景深强度」0）。对焦距离默认 = 镜头到焦点的距离（可加偏移，打关键帧做对焦转移）；「清晰范围」默认 600 m。移轴是本项目的招牌虚化，景深只在推近、需要突出某处时用 |
| 移轴 | 清晰带在画面 52% 高度处，向上下两侧渐变虚化（0.5 倍分辨率模糊、半径 1.2）；夜里减弱到 15% |
| 泛光 | bloom(强度 1, 半径 0.5, 阈值 0.62) × 泛光系数（见第 6 节） |
| 暗角 | darkness 0.9（白天）→ 1.25（夜里） |
| 全局调色（光影模式） | 暗部偏 `shadow` 色、亮部偏 `high` 色（两种色先归一到亮度 1，只改色相）；强度 = 关键帧 grade × 0.55；饱和度 = 关键帧 sat |
| 色调映射 | NeutralToneMapping，曝光 1.0（夜里 1.05）；按 SDR（Rec.709）输出。在后期链里显式做，LUT 才能作用在最终显示的颜色上 |
| 3D LUT | 可导入 .cube，「LUT 强度」调深浅；默认不用。LUT 只在本次打开页面期间有效 |
| 地名标签 | 最后叠上去，不受雾、移轴、调色、LUT 影响 |
| 「流畅」画质 | 不算 AO、移轴、景深；渲染成片时一律用精致画质 |

## 9. 镜头与输出

- 镜头视角 30°（偏长焦，压缩透视，有沙盘模型感）；北在上，不大角度旋转。
- 预设视角（`createSandbox.ts` 的 `poses`）：全貌（俯角 55°）、微缩（俯角 33°、方位 28°，默认）、细节（光明中心，3.6 km）、天际线（低机位 10° 朝北看光明中心）。
- 做视频以**航拍、全景**为主，偶尔推近。重点地标的近景细节以后做到具体镜头时再定（深圳科技馆已有 1.6 km 内自动换高精度模型）。
- 成片输出：**4K（3840×2160）60 帧，ProRes 422**（LT / HQ 可选）。字幕和花字在剪辑软件里做，沙盘只负责三维画面。
- 画面内的地名标签：直接画在画面里，同时必须提供**一键关闭**（参数「画面里的地名标签 → 显示地名标签」，或右侧「图层 → 标签」）。样式见下。
- 画幅：16:9、9:16、1:1、2.39:1。预览铺满窗口，成片的取景范围用亮框标出、框外压暗（像相机取景器），框里的构图和成片完全一样；可叠加安全框（动作安全 93%、字幕安全 90%）。
- 运动模糊默认关：60 帧本身很流畅，需要电影感时再在渲染设置里开（快门 180° 最常用）。
- 成片的抗锯齿用多帧累积：同一时刻按亚像素错开渲染多次再平均，默认 8 次。

### 地名标签样式

| 类别 | 样式 | 屏幕上的大小（底框高度占画面高度） |
|---|---|---|
| 片区（光明中心、光明城……） | 深灰蓝底 `rgba(61,74,92,.88)` + 奶油白字，600 字重；细线 + 圆点指到地面 | 3.2% |
| 地标（虹桥公园、马术中心……） | 奶油白底 `rgba(255,252,245,.93)` + 深灰蓝字 `#3d4a5c`；细线 + 圆点 | 2.5% |
| 河湖道路（茅洲河、光明大道、大的湖和水库） | 只有字（河、路名字间加空格），白字 + 深色描边，无底无线 | 2.2% |
| 地铁 / 高铁站 | 小号奶油白底（默认不显示） | 2.0% |

- 大小按屏幕比例固定，推近拉远不变；4K 成片和预览比例一致。
- 互相避让：片区 > 地标 > 河湖道路 > 站点，底框挤在一起时次要的先隐藏。
- 地标标签自动取精细地标模块的名字和位置（`landmarkModules.ts` 的 `placed`，规划示意除外）；新增地标模块后自动有标签。
- 画面标签显示时，同类的网页标签（CSS2D，不进成片）自动隐去；**讲解时**改回网页标签（站名点亮、路名浮现这些效果在网页标签上）。

## 10. 改动后的验收

改了任何影响画面的东西，至少检查：

1. **三种画面模式**：白天、夜晚、光影。
2. **光影模式的五个标准时刻**：日出 6.4、正午 12.5、黄金时刻 17.4、蓝调 19.3、深夜 23。
3. **日出日落的氛围**：至少看"玫瑰"和"紫暮"（最容易把地面染得过浓）。
4. **天气**：晴、雨、雷暴（夜里看闪电）、雾、雪（等积雪积满）。
5. **区**：光明（`http://localhost:5173/`）和至少一个其他区（如 `?district=nanshan`）；建筑最多的宝安、龙岗看帧率。
6. **讲解剧本**：从头点几拍，确认运镜、生长、标签正常。
7. **流畅度**：地址加 `?fps=1` 显示帧率。不应明显低于改动前。
8. **控制台**没有报错。
9. 改了随时间变化的效果：用"同一个任务渲两遍、逐帧比对"检查确定性（见 README「渲染成片」）。
10. 对照第 11 节的"不要做"逐条看一遍。

## 11. 不要做（来自负责人反馈）

| 不要 | 原因 / 反馈原话 |
|---|---|
| 让地面和建筑的颜色跟着天空一起浓烈 | "核心是地面还有建筑颜色太过浓烈，天空还好" |
| 让夜里的城市亮成一片、给矮楼加灯、用白光或杂色窗光 | "夜晚的建筑群的光还是乱了点，亮成了一片" |
| 夜里楼体发灰、像蒙了一层雾 | "我发现建筑还是有很重的雾感" |
| 平时出现雾（晨雾、薄霭、雨雪起雾） | 雾会让画面变脏；只在讲风的那一拍和手动选「雾」时出现 |
| 加大雨量来增强效果；白天打闪电 | "雨太大了，少了美感，闪电可以在晚上" |
| 不同水体用同一种颜色 | "颜色都一样，没有深浅变化" |
| 砍掉清晨的几种蓝调 / 日出日落氛围 | "以前好几种色调的清晨蓝调，没了"（已补回，不要再删） |
| 随手加彩色灯光 | 彩色光只给少数有现实依据的地标，一个地标一种颜色 |
| 镜头大角度旋转、不再北在上 | 北在上是讲解和读图的基础 |
| 追求和旧 WebGL 版一模一样；做 WebGL 降级对比 | "目标不是一模一样……按照我们原本美术风格目标去调试"；全面走 WebGPU |

内容上的规则（讲解剧本）：语气娓娓道来、少讲规划、不讲未来；没有出处不说"深圳最××"；光明不与南山接壤；「光明站」指 6 号线光明站（科学公园一带），不是光明城站。

## 12. 技术规范（写代码时必须遵守）

### 渲染

- **只用 WebGPU**：Three.js r186 的 `three/webgpu`（`WebGPURenderer`，不支持时自动降级 WebGL2）和 `three/tsl` 节点。vite 把所有 `import "three"` 指向 `three/webgpu`。
- **禁止**：`onBeforeCompile`、`ShaderMaterial`、`RawShaderMaterial`、手写 GLSL、`EffectComposer`。这些在 WebGPU 下不生效。
- 材质效果一律走 `scene/nodes.ts` 的 `addColorMod` / `addEmissive` / `addOutputMod` / `addMask` / `setPosition`。效果注册表放在 WeakMap 里，不放 `material.userData`（`clone()` 会把 userData 深拷贝，节点会坏掉）。
- 节点表达式不要包在 `Fn` 里给材质用（同一材质会被主渲染和阴影各编译一次，Fn 里的临时变量会出错）。
- 粒子、光点用 `SpriteNodeMaterial` / `PointsNodeMaterial` + 实例化（WebGPU 不支持大于 1 像素的点）。
- 顶点里读到的存储缓冲要用 `varying()` 传给片元。区界遮罩纹理必须 `flipY = false`。
- 一个 `reflector()` 只能给一组水面材质用。
- 体积雾用 `VolumeNodeMaterial`：它所在的图层里必须有灯光；它不响应 `DirectionalLight`，太阳照雾用 `SpotLight`；雾灯的阴影相机只拍普通物体层（`layers.set(0)`）。聚光灯要在雾里出光柱，也要加进"太阳照雾"层。

### 结构（`app/sandbox/`）

```
page.tsx            页面和右侧面板（React）
scene/              3D 场景：createSandbox.ts 总装（数据、场景、后期、step / 渲染循环、讲解、做视频的接线）
                    artPalette.ts 一天的关键色 / atmosphere.ts 光影驱动 / weather.ts 天气 / palette.ts 物体色板
landmarks/          各地标模型（光明在根目录，其他区按区分文件夹）
studio/             做视频用的工具：参数表、预设、时间线、运镜、离屏出帧、渲染任务、画面标签、路灯光点、面板
```

- **新的可调参数一律登记在 `studio/params.ts`**：登记后自动出现在参数面板、预设、时间线（可打关键帧）里。不要在别处另做滑块。
- 参数是"在自动配色上再调"的倍数或开关，默认值 = 规范认可的画面；在 `scene/atmosphere.ts` 的 `finalize()` 和 `createSandbox.ts` 的 `step()` 里读取后写进 uniform、灯光。
- 时间线库（Theatre.js）只在 `studio/timeline.ts` 里出现；以后换时间线工具只改这一个文件。
- 画面模式、时刻、天气通过 `LookControl`（`studio/presets.ts` 定义，`createSandbox.ts` 实现）读写；预设、时间线都只走它。
- **颜色和美术参数**放在 `scene/palette.ts`、`scene/artPalette.ts`，或作为 uniform 由 atmosphere 写入；不要散落在各个文件里写死。
- 代码注释用中文，写"为什么"，说人话。

### 坐标与数据

- 单位米；**x 向东，z 向南**，y 向上；原点为光明区中心。各区同一投影（`sandbox.json` 的 `meta.projection`，WebMercator × cos(lat0)）。
- 经纬度 → 沙盘坐标用 `scene/landmarks.ts` 的 `projectLngLat`。
- 地表高度一律用 `terrain.heightAt`（已含高程夸张）；高程夸张用 `scene/palette.ts` 的 `exaggerate`。

### 确定性（成片要能逐帧复现）

- 所有随时间变化的东西只在 `createSandbox.ts` 的 `step(delta)` 里推进。实时预览时 delta 是真实时间，渲染成片时固定 1/60 秒。
- 着色器里的时间用 `studio/clock.ts` 的 `simTime`，**不要用 `three/tsl` 的 `time`**（那是真实时间，渲染成片时会和画面对不上）。
- 随机数用 `studio/clock.ts` 的 `rng()`，**不要用 `Math.random()`**。着色器里用 `hash()` 这类固定的伪随机。
- 能写成"模拟时间的函数"的就不要逐帧累加（例：云的位置 = 起点 + 速度 × simTime）。必须有内部状态的（天气状态机、atmosphere），要提供快照和恢复，并在 `createSandbox.ts` 的 `captureScene` / `restoreScene` 里接上。
- 会动的地标：在 `object.userData.tick(delta, elapsed)` 里更新，`elapsed` 就是模拟时间。
- 任何效果都不能依赖窗口大小或帧率：成片固定 3840×2160、60 帧，与窗口无关。
- 新增效果后，用"同一个任务渲两遍、逐帧比对"检查。
